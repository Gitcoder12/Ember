# Ember — README Quality Checklist

## Beginner
- [ ] First paragraph explains the problem and benefit in ordinary language.
- [ ] A simple example explains the user journey.
- [ ] New terms are defined.
- [ ] Quick Start has prerequisites and expected output.

## Engineer / researcher
- [ ] Architecture and data flow match actual code.
- [ ] Inputs, outputs, dependencies and failure modes are documented.
- [ ] Tests, benchmarks, data provenance and reproduction steps are linked.
- [ ] Simulation, sample data, estimates and limitations are clearly labelled.

## Contributor
- [ ] Roadmap, activity log, company-fit and contribution instructions are linked.
- [ ] Work packages have measurable acceptance criteria.
- [ ] No claim exceeds the evidence.
